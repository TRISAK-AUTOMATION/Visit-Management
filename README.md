# TRISAK Visit Management System

ระบบบริหารจัดการคำขอออกนอกสถานที่ (Visit Request) ตามแบบที่ออกแบบไว้ในภาพ Mockup
ประกอบด้วย หน้า Login, Dashboard, สร้างคำขอ Visit, My Requests, Approve Requests,
ปฏิทิน, Customer, Report, Notifications, โปรไฟล์ และหน้า Admin จัดการผู้ใช้งาน
โดยเมนูจะถูกจำกัดตาม **สิทธิ์การใช้งาน (Role)** ของผู้ใช้แต่ละคนโดยอัตโนมัติ

สแตกที่ใช้ (ตั้งใจให้เรียบง่าย ติดตั้งง่าย ไม่ต้องพึ่งเซิร์ฟเวอร์ฐานข้อมูลแยก):

- **Backend:** Node.js + Express (REST API)
- **ฐานข้อมูล:** SQLite (ไฟล์เดียว จบ ไม่ต้องติดตั้งโปรแกรมฐานข้อมูลเพิ่ม) ผ่านไลบรารี `better-sqlite3`
- **Frontend:** React (Vite) — เรียก API เดิมด้วย `fetch` ผ่าน `client/src/lib/api.js` (โค้ด Vanilla JS ชุดเดิมยังเก็บสำรองไว้ที่ `public-legacy/`)
- **Auth:** Session-based login (`express-session`) + เข้ารหัสรหัสผ่านด้วย `bcryptjs`
- **PDF:** สร้างเอกสาร PDF ด้วย `pdfkit` (เป็นไลบรารี JavaScript ล้วน ไม่ต้องคอมไพล์ ไม่มีปัญหากับ Windows) ใช้ฟอนต์ Sarabun ที่รวมชุดอักษรไทย+อังกฤษไว้ในไฟล์เดียว (อยู่ในโฟลเดอร์ `fonts/`)
- **อีเมล:** แจ้งเตือน/อนุมัติผ่านอีเมลด้วย `nodemailer` (ดูหัวข้อ 7)

## 0. Frontend เป็น React แล้ว (สำคัญ อ่านก่อนรัน)

โปรเจกต์นี้แยก Backend (Express, โฟลเดอร์หลัก) กับ Frontend (React, โฟลเดอร์ `client/`) ออกจากกัน:

```bash
# ครั้งแรก ติดตั้งทั้งสองฝั่ง
npm install              # ติดตั้ง backend (Express ฯลฯ)
cd client && npm install # ติดตั้ง frontend (React, Vite, react-router-dom)
cd ..

# วิธีที่ 1: รันแบบ Production (แนะนำสำหรับใช้งานจริง)
cd client && npm run build   # build React ออกไปที่ ../public โดยอัตโนมัติ
cd ..
npm start                    # Express serve ทั้ง API และหน้าเว็บที่ build แล้ว ที่ http://localhost:3000

# วิธีที่ 2: รันแบบ Dev (แก้โค้ดแล้วเห็นผลทันที ไม่ต้อง build ใหม่ทุกครั้ง)
npm start                    # เทอร์มินัลที่ 1: รัน Express API ที่ port 3000
cd client && npm run dev     # เทอร์มินัลที่ 2: รัน Vite dev server ที่ port 5173 (proxy /api ไปยัง :3000 ให้อัตโนมัติ)
# เปิดเบราว์เซอร์ที่ http://localhost:5173 (ไม่ใช่ 3000) ตอน dev
```

โค้ดหน้าเว็บชุดเดิม (HTML+Vanilla JS) ถูกย้ายไปเก็บสำรองไว้ที่โฟลเดอร์ `public-legacy/` เผื่อต้องการอ้างอิงหรือย้อนกลับ ไม่ได้ถูกลบทิ้ง
โฟลเดอร์ `public/` (ที่ Express serve จริง) ตอนนี้จะถูก `npm run build` เขียนทับด้วยไฟล์ React ทุกครั้งที่ build ใหม่

## 2. ฐานข้อมูล (Schema)

ไฟล์ `db/database.js` จะสร้างตารางเหล่านี้ให้อัตโนมัติเมื่อรันเซิร์ฟเวอร์ครั้งแรก:

| ตาราง | ใช้เก็บอะไร |
|---|---|
| `users` | ผู้ใช้งานระบบ, username/รหัสผ่าน (เข้ารหัส), ตำแหน่ง, **role** (Employee / Approver / Admin) |
| `customers` | ข้อมูลลูกค้า/บริษัทที่จะไปเยี่ยม (รหัสลูกค้า, ชื่อ, ผู้ติดต่อ, เบอร์โทร) |
| `visit_requests` | คำขอออกนอกสถานที่ทั้งหมด พร้อมสถานะ pending/approved/rejected/cancelled |
| `approval_history` | ประวัติการดำเนินการของแต่ละคำขอ (ส่งคำขอ / อนุมัติ / ไม่อนุมัติ / ยกเลิก) |
| `notifications` | การแจ้งเตือนของผู้ใช้แต่ละคน |

**สิทธิ์การใช้งาน (Role) มี 3 ระดับ:**
- `Employee` (พนักงาน/ผู้ขออนุมัติ) — สร้างคำขอ, ดูคำขอของตัวเอง
- `Approver` (ผู้อนุมัติ) — ทำทุกอย่างที่ Employee ทำได้ + อนุมัติ/ไม่อนุมัติคำขอของทุกคน
- `Admin` (ผู้ดูแลระบบ) — ทำได้ทุกอย่าง + จัดการผู้ใช้งานทั้งหมด

**ฟิลด์ในคำขอ Visit (visit_requests)** ตามที่เคยเก็บใน Google Sheet เดิม ตอนนี้มีครบแล้วในระบบ:
วันที่, ประเภทงาน (Job Type), ลูกค้า/บริษัท, รหัสลูกค้า, ผู้ดูแลการขาย (Sales), ทะเบียนรถ, ไมล์ออก/ไมล์เข้า,
เวลาออก/เวลากลับ (ตามแผน และเวลาจริง), จำนวนชั่วโมง OT, คนติดต่อ, สินค้า, รายละเอียดงาน, ผู้ร่วมงาน,
Remark, เลขประจำตัวผู้เสียภาษีลูกค้า (Cus. TAX ID), วันที่ออกใบกำกับภาษี (TAX ID & Date)
รวมถึงสถานะอนุมัติ (Approve Status) และประวัติการอนุมัติแบบเต็ม

## 3. วิธีติดตั้งและรันหลังจากได้โค้ดแล้ว

### ขั้นตอนที่ 1: ติดตั้ง Node.js
ต้องมี **Node.js เวอร์ชัน 18 ขึ้นไป** ในเครื่อง ถ้ายังไม่มี ดาวน์โหลดได้ที่ https://nodejs.org
ตรวจสอบเวอร์ชันด้วยคำสั่ง:
```bash
node -v
npm -v
```

### ขั้นตอนที่ 2: ติดตั้งไลบรารีที่จำเป็น
เปิด Terminal / Command Prompt เข้าไปที่โฟลเดอร์โปรเจกต์ (โฟลเดอร์ที่มีไฟล์ `package.json`) แล้วรัน:
```bash
npm install
```
คำสั่งนี้จะติดตั้ง Express, better-sqlite3, express-session, bcryptjs ให้อัตโนมัติ

### ขั้นตอนที่ 3: สร้างฐานข้อมูล + ใส่ข้อมูลตัวอย่าง
```bash
npm run seed
```
คำสั่งนี้จะ:
- สร้างไฟล์ฐานข้อมูล `db/trisak.db`
- ใส่ผู้ใช้ทดสอบ 4 คน, ลูกค้าตัวอย่าง 5 บริษัท, คำขอ Visit ตัวอย่าง และการแจ้งเตือน
- **หมายเหตุ:** ถ้ารันซ้ำ ข้อมูลเก่าจะถูกล้างแล้วสร้างใหม่ทั้งหมด (ใช้สำหรับรีเซ็ตข้อมูลทดสอบ)

### ขั้นตอนที่ 4: เริ่มรันเซิร์ฟเวอร์
```bash
npm start
```
เมื่อรันสำเร็จจะเห็นข้อความ:

## 4. การใช้งานแต่ละหน้าจอ (สรุปสั้นๆ)

1. **Dashboard** — สรุปจำนวนคำขอทั้งหมด/รออนุมัติ/อนุมัติแล้ว/ไม่อนุมัติ พร้อมรายการล่าสุดและกำหนดการที่จะถึง
2. **สร้างคำขอ Visit** — กรอกแบบฟอร์ม เลือกลูกค้า วันเวลา วัตถุประสงค์ แล้วกด "ส่งคำขอ" ระบบจะสร้างเลขที่คำขอ (เช่น `VR-2026-00009`) และแจ้งเตือนไปยังผู้อนุมัติทุกคนอัตโนมัติ
3. **My Requests** — ดูคำขอของตัวเอง กรองตามสถานะ, ดูรายละเอียด/ประวัติการอนุมัติ, ยกเลิกคำขอที่ยังรออนุมัติได้
4. **Approve Requests** *(เห็นเฉพาะ Approver/Admin)* — ดูคำขอที่รออนุมัติ กดอนุมัติ/ไม่อนุมัติ พร้อมใส่ความคิดเห็นได้
5. **ปฏิทิน** — ดูคำขอ Visit ในรูปแบบปฏิทินรายเดือน เลื่อนดูเดือนก่อน/ถัดไปได้
6. **Customer** — เพิ่ม/แก้ไข/ลบ ข้อมูลลูกค้า (รหัสลูกค้าจะถูกสร้างให้อัตโนมัติ เช่น `CUS-006`)
7. **Report** — สรุปสัดส่วนสถานะคำขอ และจำนวนคำขอแยกตามลูกค้า
8. **Notifications** — ดูการแจ้งเตือนทั้งหมด กดที่รายการเพื่อทำเครื่องหมายว่าอ่านแล้ว
9. **โปรไฟล์** — แก้ไขข้อมูลส่วนตัวและเปลี่ยนรหัสผ่าน
10. **จัดการผู้ใช้งาน** *(เห็นเฉพาะ Admin)* — เพิ่ม/แก้ไข/ลบผู้ใช้ และกำหนดสิทธิ์ (Employee/Approver/Admin)
11. **พิมพ์ PDF** — ในหน้า My Requests และ Approve Requests กดปุ่ม "📄 พิมพ์ / ดูตัวอย่าง PDF" ที่แต่ละรายการ
    หรือในหน้ารายละเอียดคำขอ ระบบจะสร้างเอกสาร PDF 1 หน้า พร้อมข้อมูลครบทุกฟิลด์ (รวมไมล์, OT, เลขภาษี ฯลฯ)
    และช่องลายเซ็นผู้ขอปฏิบัติงาน/ผู้ตรวจสอบ/ผู้อนุมัติ พร้อมพิมพ์ได้ทันทีจากเบราว์เซอร์ (Ctrl+P)

## 5. คำถามที่พบบ่อย

**Q: ต้องติดตั้งโปรแกรมฐานข้อมูล เช่น MySQL หรือไม่?**
A: ไม่ต้อง ระบบนี้ใช้ SQLite ซึ่งเป็นไฟล์ฐานข้อมูลตัวเดียว (`db/trisak.db`) ไม่ต้องติดตั้งอะไรเพิ่ม เหมาะสำหรับทดสอบ/เดโม หรือใช้งานจริงในองค์กรขนาดเล็ก-กลาง

**Q: อยากเปลี่ยนไปใช้ MySQL/PostgreSQL ในอนาคตทำอย่างไร?**
A: โค้ดฝั่ง API (`routes/*.js`) เรียกใช้ฐานข้อมูลผ่านไฟล์ `db/database.js` ไฟล์เดียว ถ้าต้องการย้ายไปใช้ MySQL ก็แก้เฉพาะไฟล์นี้ให้เชื่อมต่อผ่านไลบรารีเช่น `mysql2` แทน `better-sqlite3` โดยคง SQL query ส่วนใหญ่ให้ใกล้เคียงเดิม (SQL มาตรฐานใกล้เคียงกัน)

**Q: อยากรีเซ็ตข้อมูลกลับไปเป็นค่าเริ่มต้นทำอย่างไร?**
A: รันคำสั่ง `npm run seed` อีกครั้ง (ข้อมูลเก่าทั้งหมดจะถูกลบแล้วใส่ข้อมูลตัวอย่างใหม่)

**Q: ลืมรหัสผ่านผู้ใช้ทดสอบ?**
A: รหัสผ่านของทุกบัญชีที่สร้างจาก seed คือ `123456`

**Q: ระบบส่งอีเมลแจ้งเตือนได้ไหม และอนุมัติผ่านอีเมลได้ด้วยหรือไม่?**
A: ได้แล้ว ✅ เมื่อมีคนส่งคำขอ ระบบจะ (1) แจ้งเตือนในเว็บแอป (กระดิ่ง Notifications) และ (2) ส่งอีเมลไปหาผู้อนุมัติทุกคนที่เปิดรับอีเมลไว้พร้อมกัน
โดยอีเมลจะมีปุ่ม **"✓ อนุมัติ"** / **"✕ ไม่อนุมัติ"** ให้กดยืนยันได้ทันที (ไม่ต้อง login) หรือจะกดลิงก์ "ดูรายละเอียด/อนุมัติผ่านเว็บแอปพลิเคชัน" เพื่อเข้าสู่ระบบก็ได้ — เลือกช่องทางไหนก็ได้ ระบบซิงก์สถานะให้อัตโนมัติ
(ถ้าอนุมัติผ่านเว็บแล้ว ลิงก์ในอีเมลจะใช้ซ้ำไม่ได้ และในทางกลับกัน) จากนั้นจะมีอีเมลแจ้งผลกลับไปยังผู้ขออีกฉบับด้วย
รายละเอียดวิธีตั้งค่า SMTP ดูได้ในไฟล์ `.env.example`

**Q: ต้องการ Deploy ขึ้นใช้งานจริงบนอินเทอร์เน็ต ทำอย่างไร?**
A: อัปโหลดทั้งโฟลเดอร์ขึ้นเซิร์ฟเวอร์ที่รองรับ Node.js (เช่น VPS, Render, Railway) ตั้งค่า environment variable
`PORT` ตามที่ผู้ให้บริการกำหนด แล้วรัน `npm install && npm run seed && npm start`
(แนะนำเปลี่ยนค่า `secret` ในไฟล์ `server.js` ส่วนของ `express-session` เป็นค่าใหม่ที่คาดเดายากก่อนใช้งานจริง)

**Q: มีทดสอบว่าใช้งานได้จริงหรือยัง?**
A: ทดสอบ API หลักแล้ว (เข้าสู่ระบบทั้ง 3 สิทธิ์, สร้างคำขอ, อนุมัติ/ไม่อนุมัติ, จัดการผู้ใช้) ทำงานได้ถูกต้องตามที่ออกแบบไว้

- ✅ **สร้าง/พิมพ์ PDF อัตโนมัติ — ทำเสร็จแล้ว** กดปุ่ม "พิมพ์ / ดูตัวอย่าง PDF" ในหน้า My Requests หรือ Approve Requests ได้เลย
- ✅ **แจ้งเตือนทางอีเมล + อนุมัติผ่านลิงก์ในอีเมล — ทำเสร็จแล้ว** ดูวิธีตั้งค่าในหัวข้อ 7 ด้านล่าง

หากต้องการให้ช่วยพัฒนาต่อในส่วนที่ยังไม่ได้ทำ (อัปโหลดรูปโปรไฟล์ ฯลฯ) แจ้งได้เลยครับ

## 7. การตั้งค่าแจ้งเตือนทางอีเมล (Email Notification)

1. ติดตั้งไลบรารีที่เพิ่มเข้ามา: `npm install` (จะติดตั้ง `nodemailer` และ `dotenv` เพิ่มจากเดิม)
2. คัดลอกไฟล์ `.env.example` เป็น `.env` แล้วใส่ค่า SMTP ของบริษัท (หรือใช้ Gmail/Outlook/SendGrid ก็ได้) พร้อมตั้ง `APP_BASE_URL`
   ให้เป็นโดเมนจริงที่ผู้ใช้จะเปิดเว็บแอปนี้ (ใช้สร้างลิงก์ในอีเมล)
3. รัน `npm start` ตามปกติ — ถ้ายังไม่ตั้งค่า SMTP ระบบจะไม่ล้ม แต่จะ log ตัวอย่างอีเมลออกทาง console แทน (โหมดพัฒนา) ทำให้ทดสอบ flow ได้โดยไม่ต้องมี SMTP จริง
4. ผู้ใช้แต่ละคน (โดยเฉพาะผู้อนุมัติ) สามารถเปิด/ปิดการรับอีเมลได้เองที่หน้า "โปรไฟล์ของฉัน" (checkbox "รับการแจ้งเตือนทางอีเมล")
5. กลไกการทำงาน:
   - เมื่อพนักงานส่งคำขอ → ระบบสร้าง notification ในเว็บ + ส่งอีเมลไปยังผู้อนุมัติทุกคน โดยแต่ละฉบับมีลิงก์อนุมัติ/ไม่อนุมัติเฉพาะของตัวเอง (token) ที่ใช้ได้ครั้งเดียวและหมดอายุใน 7 วัน
   - ผู้อนุมัติกดปุ่มในอีเมล → ระบบแสดงหน้ายืนยัน (กันการกดโดยไม่ตั้งใจ/บอทสแกนลิงก์) ก่อนบันทึกผลจริง
   - ไม่ว่าจะอนุมัติผ่านอีเมลหรือผ่านเว็บแอป ระบบใช้ตรรกะเดียวกัน (`applyDecision` ใน `routes/visitRequests.js`) และตรวจสถานะคำขอทุกครั้ง ทำให้ทั้งสองช่องทาง**ซิงก์กันเสมอ** — ถ้าฝั่งหนึ่งอนุมัติไปแล้ว อีกฝั่งจะเห็นข้อความ "คำขอนี้ถูกดำเนินการไปแล้ว" ทันที
   - เมื่อมีผลอนุมัติ/ไม่อนุมัติ (จากช่องทางใดก็ตาม) ระบบจะส่งอีเมลแจ้งผลกลับไปยังผู้ขอโดยอัตโนมัติ พร้อมระบุว่าดำเนินการผ่านช่องทางไหน
